### 1.2 核心功能

1. **独立视图页签**：插件注册自定义视图，点左侧 ribbon 图标 / 执行命令「打开个人工作台」/ 启动自动打开，以独立页签呈现完整工作台；顶部横幅与查询栏固定，**左右两栏独立上下滚动**（为后续扩展卡片预留空间）
2. **顶部横幅（统计）**：参考 apex-dashboard 的 `dashboard-banner-stats` 三栏布局——左栏 4 项库统计（附件/文件夹/标签/属性，Hearth Vault 卡片三段式：图标|数字|文字）、中栏（累计活跃天数 + 本周/本月/本季/本年/近N天编辑数 + 自适应热力图）、右栏 4 项（任务完成率/连通度/孤立率/链接每篇）
3. **编辑日志**：监听 `modify`/`create`/`delete` 事件，按"当天编辑过的不同笔记数"持久化记录（同篇多次编辑只算 1 篇、新建计入、删除移除、附件排除），作为热力图与全部活跃统计的精确数据源
4. **查询栏**：参考 hearth 插件，支持搜索笔记 / 任务 / 输入命令，白色背景高亮
5. **天气卡片 + 当天农历 + 每日一签**：和风天气实时天气 + 未来 6 天预报；天气下方附当天农历信息（干支纪年、生肖、农历月日、当日节日）；引用语为**每日一签**（按日期哈希确定性选取，每天不同，分两行展示）；天气卡片显示 API 来源；生活指数一行折叠、点击展开详情；请求频率可在设置中配置
6. **年度进度**：当年已过百分比 + 已过/剩余天数进度条
7. **今日任务 + 逾期任务 + 后续任务**：全库扫描任务，只显示有 `⏳ scheduled` 日期的任务；某日无 scheduled 时回退显示 `📅 due`；逾期任务红色显示；任务按描述中的时间点自动排序；**工作台直接勾选即写回笔记中的 tasks 任务**；逾期/后续支持滑动查看全部（默认显示 5 条）
8. **生日提醒**：从数据笔记【个人工作台数据】→「## 生日日期」读取（姓名，称呼，农历出生年月日；无日期自动跳过），自动换算为今年/明年的公历日期并倒计时；农历写法完全按笔记原文；显示称呼 + 农历月日，头像圈内显示姓氏
9. **农历万年历**：公历/农历双历日历，标注节气、节日（分开展示）、生日（橙色点）、任务徽标、**生活安排**（回家/旅行等，紫色，从数据笔记「## 生活安排」表格读取）；日历顶部中间显示当前时间（时:分，每分钟刷新）；支持法定节假日与**单双休**（从数据笔记「## 单双休安排」表格读取，每周一行：周期 / 日期 / 休息日，休息日填「周日」单休、「周六、周日」双休，休息日以明显红色背景标示）；点击任意日期在下方展示黄历详情（当日农历/干支/宜/忌）与当天全部任务（含已完成，自动勾选）

### 1.3 参考插件

- **apex-dashboard**：顶部统计横幅（三栏布局/图标/热力图 auto-fill/进度条/今天标记/右栏 4 指标公式）、天气卡片 + 当天农历、日历/农历万年历、年度进度、每日一签算法
- **hearth**：查询栏样式与交互、Vault 卡片统计方式（附件/文件夹/标签/属性）

### 1.4 关键设计决策

| 决策点 | 结论 | 原因 |
|--------|------|------|
| 呈现方式 | 独立视图页签 | 用户实测后确认"嵌入笔记不合适"，改为独立页签，与 Obsidian 标签体系一致 |
| 任务统计口径 | 只统计 `⏳ scheduled` 日期，无则回退 `📅 due` | 用户明确要求，避免无关任务混入日历 |
| 生日农历写法 | 完全按笔记原文展示 | 用户明确要求"不要有数字"，如"八月十二"而非"农历八12" |
| 农历计算 | 内嵌 lunar-javascript（约 425KB） | 离线可用、无网络依赖、计算精确 |
| 活跃统计数据源 | **mtime 全量基线 + 编辑日志按天覆盖** | 新装插件无编辑日志时先用 md 最后编辑时间统计；启用后以逐次编辑计数覆盖，历史不丢失 |
| 统计去重 | 周期统计按"不同笔记数"去重 | 同一篇跨天编辑只算 1 次，避免篇次累加虚高 |
| 热力图布局 | 3 行排满、列数随中栏宽度自适应 | 用户要求"根据窗口大小自动调整数量，3 行每行排满" |
| 天气服务 | 和风天气（国内 API，Key 可配） | 用户要求国内 API，精度与更新频率更优；`data.json` 保留 Key 配置（关插件不丢失） |

## 2. 统计口径规范

> 本章是统计类功能的唯一口径依据，改动需同时更新本章、源码与测试。

### 2.1 数据源与分层

| 层 | 说明 |
|----|------|
| **有效编辑时间基线** | 每次统计扫描全部 md 笔记的"**有效最后编辑时间**"按天聚合：**frontmatter `modified` 优先**（Frontmatter Date Manager 随正文变化维护，比 mtime 可靠）→ 缺失/解析失败/未来 >1 天异常值回退 `updated` → 再回退 `stat.mtime`（v1.5.24 起；此前的纯 mtime 基线保留为兜底）——作为历史基线，覆盖所有有记录的日期 |
| **唯一判定原则（实时）** | 插件运行期间的编辑计数**只认"正文发生变化"的保存**：启动时异步预扫全库正文 hash 基线（正文=去掉开头 `---...---` frontmatter 后的内容，FNV-1a 32 位 hash），每次 `modify` 事件读取当前正文比对——**正文 hash 未变一律不计入**（覆盖移动/重命名、仅改 frontmatter 属性、Obsidian 启动伪事件等所有"未改正文"的情况）；正文变了才计入并更新缓存；**新建文件（无基线）正常计入**，由批量导入检测识别导入 |
| **编辑日志 editLog** | 插件运行期间按上述唯一原则，监听 `modify`/`create`/`delete` 事件，按"当天编辑过的不同笔记数"计数（同篇去重、新建计入、删除移除、附件非 md 排除），持久化到 `data.json`。**启动误报防护**：Obsidian 启动/重载会对存量旧文件误触发 modify/create（mtime 为过去时间），事件文件 `stat.mtime` 距今超过 2 分钟一律忽略（省读取，正文比较为第二道闸） |
| **移动排除 movedLog** | 实时场景已由"正文未变不计入"覆盖（rename 时正文 hash 基线从旧路径迁移到新路径，防止新路径无基线误计）。**movedLog 仅用于 mtime 基线阶段**（插件未运行的历史日期）：监听 `rename` 记入 `movedLog{日期:[路径]}`，统计时过滤移动日的文件（保留 400 天自动清理） |
| **导入排除 importLog** | 外部批量导入的笔记**不计入编辑计数**（导入=新文件入库，非用户编辑）：①实时识别——同顶层目录 10 分钟窗口内 create ≥ 30 篇判定为批量导入，**入队前校验 mtime 时效**（仅 mtime 距今 ≤2 分钟的"真新建/真复制"才纳入，防 Obsidian 启动伪 create）；②启动回溯——**全量历史扫描**（mtime 基线阶段兜底），三种判定任一命中即记入排除：**「目录|小时」≥30 篇**（单目录批量）、**「全库|分钟」≥30 篇**（整库同步，如 Git pull/云同步把 mtime 统一改写）、**「同日 10 分钟滑动窗口」≥15 篇**（连续几分钟内旧文件被批量改写）；判定结果记入 `importLog{日期:[路径]}` 全链路排除，并回滚当天编辑集合 |
| **从未编辑排除 neverEdited** | **mtime 基线阶段兜底**：创建时间与最后编辑时间一致（差值 ≤ 3 秒）的文件视为导入/空笔记，永远不计入编辑统计（实时场景已被"正文未变"覆盖；该规则用于插件未运行的历史日期）——从热力图、活跃天数、本周/本月/本季/本年、近N天全链路排除 |
| **覆盖规则** | **笔记级覆盖（v1.5.23 起，最高优先）**：有正文编辑日志（editLog 数组明细）的笔记完全按日志日期统计（`_hasLog`），其 modified/mtime 不参与任何计数——仅改元属性造成的 mtime/时间字段变化一律不误计；无日志笔记按上表"有效编辑时间基线"；editLog 有记录的日期再覆盖基线 |

### 2.2 editLog 存储格式

| 日期范围 | 存储值 | 说明 |
|----------|--------|------|
| 本月内 | **文件路径数组**（`["工作/a.md","生活/b.md"]`） | 供本周/本月/本季/本年跨天去重统计 |
| 历史月份 | **数字**（篇数） | 压缩体积，不参与文件级去重（mtime 基线已覆盖） |

- 落盘防抖 2 秒，插件卸载时冲刷保存
- 旧版数字格式自动兼容（`dayHist` 覆盖取 `v.length` 或数字本身）

### 2.3 各指标口径

| 指标 | 口径 | 备注 |
|------|------|------|
| **活跃天数** | 累计有编辑记录的总天数（`activeDates.size`） | 非连续 streak；断档不归零，只增不减 |
| **本周/本月/本季/本年 X篇** | 期间内**编辑过的不同笔记数**（去重） | 有效最后编辑时间（modified→updated→mtime）+ editLog 文件列表取并集；同篇跨天只算 1；有正文日志的笔记只按日志算。**期间起止：本周=自然周（周一 0 点~周日，v1.5.26 起）**；本月/本季/本年=自然月/季/年 |
| **近N天 X篇** | 热力图窗口（N = 当前列数 × 3）内编辑过的不同笔记数（去重） | 与热力图同窗口，窗口随横幅宽度自适应 |
| **热力图格子** | 当天编辑的笔记篇数（editLog 覆盖后） | 不跨天去重（格子是"天"维度）；**移动/重命名的笔记不计入**；**导入的笔记不计入**；**创建后从未编辑（mtime=ctime≤3s）的笔记不计入** |
| 任务完成率 | 已完成任务 ÷ 总任务 ×100%（扫描全库 `- [ ]` / `- [x]`） | apex 公式 |
| 连通度 | (总笔记 − 孤立笔记) ÷ 总笔记 ×100% | 有链接关系笔记占比 |
| 孤立率 | 孤立笔记 ÷ 总笔记 ×100% | 既无出链也无人链接 |
| 链接/篇 | 总链接 ÷ 总笔记（进度条按 ÷3 封顶） | 平均每篇出链数 |
| 附件/文件夹/标签/属性 | Hearth Vault 卡片口径：非 md = 附件、非根目录 = 文件夹、标签去重、frontmatter 键去重 | 左栏横幅 |

### 2.4 热力图强度分级

```
取窗口内单日最大值 max；每格 r = 当天篇数 ÷ max
r=0 → 灰底 10%；r≤0.25 → l1 35%；r≤0.5 → l2 55%；r≤0.75 → l3 78%；r>0.75 → l4 100%
今天格子加白框标记（--today）
```

- 格子 12×12px、间距 4px、圆角 2px、单色（横幅 accent 色）按不透明度分 4 档
- **列数自适应**：`列数 = max(6, floor((中栏宽 + 4) / 16))`，默认 24 列；点数 = 列数 × 3（恒 3 行排满）；`--heat-cols` CSS 变量驱动网格列数，窗口缩放经 ResizeObserver 自动重绘
- 时间窗口 = 最近 N 天（N = 列数 × 3，默认 24 列 → 72 天；窗口随宽度自适应，无固定上限），今天在最后一个格子
- **悬停提示（tooltip）**：鼠标悬停任意热力点显示该格日期与当天编辑数（如"2026年9月8日 周二 · 编辑 2 篇"），随鼠标移动、离开自动消失；格子带 `data-ymd`/`data-n` 属性

### 2.5 同步与多设备注意

- editLog 存在插件 `data.json`，随 vault 同步（Obsidian Sync / 网盘）；**历史日期同步后准确**
- **唯一偏差场景**：两台电脑同一天都编辑——data.json 整体覆盖（后写覆盖先写），当天计数只反映最后同步的一台；不同日期历史始终准确

## 3. 设计要求

> 用户明确提出的视觉/交互要求，改动不得违反。

### 3.1 横幅（顶部）

- **三栏布局**：左栏窄、中栏宽、右栏窄；左栏 4 项统计为三段式（图标|数字|文字，间隔 6px）；中栏文字居中；中栏与左右栏无大间隔
- **活跃点数**不挤在一起：间距 4px、格子 12px、3 行排满、居中偏下；整体高度尽量低（热力点小、间距大时压缩行数）
- 横幅高度适中（用户多次要求"缩小"），字体略小
- 左栏 4 项 = 附件/文件夹/标签/属性（图标 + 数字 + 文字）

### 3.2 布局与滚动

- 工作台锁定视口高度，**左右两栏独立上下滑动**，顶部横幅与查询栏固定
- 后续新增卡片都加在左/右栏内，各自滚动互不影响

### 3.3 日历

- 顶部：月份（左）、当前时间 时:分（中，每分钟刷新）、今天按钮（右）
- 节气和节日**分开体现**；休息日不改变数字颜色，用**格子内背景色**区分（更显眼）
- 单双轮休**从笔记【个人工作台数据】读取**（`## 单双休安排` → `### 2026年` 表格，`休息日`列填「周日」单休 /「周六、周日」双休；插件按 ISO 周号表驱动判定，缺省双休）。旧 `restMode/singleDay/sdStart/manualWeeks` 设置字段保留兼容旧 data.json，不再使用
- 法定节假日内置（按国务院通知按年更新），调休上班日灰色
- **生活**（原"活动"改名）从笔记读取，紫色 `#c084fc`；国庆等假期日内也**全量显示**（与节日文字两行同格）
- 颜色体系：假期红 `#ef4444`（`.wb-hol`）、节日琥珀 `#f59e0b`（`.wb-fest`）、节气绿 `#7fd6b0`（`.wb-jq`）三色各归其位，与图例一致
- 任务徽章（蓝点）：**当天有任务记录（含已完成）即保留**，下方数字=未完成数，全部完成后数字为 0；悬停显示"共 N 个任务（M 未完成）"
- 自定义公历节日表 `EXTRA_SOLAR_FEST`（键 MM-DD，跨年复用）：补充 lunar 库未收录的国际日/纪念日（注：10-05 世界住房日库已内置，无需重复添加）
- 图例：任务 / 生日 / 节日 / 节气 / 假期 / 生活（6 类小圆点）

### 3.4 任务

- 当天任务按描述内时间点自动排序（`parseTaskTime`）
- 日期前图案（Tasks 插件语义）：`⏳` 表示 scheduled（计划开始）、`📅` 表示 due（截止）；**任务名颜色：scheduled 白色、有 due 红色；时间文字一律白色**
- 笔记名称固定宽度 200px 右对齐，超长换行；日期与笔记名固定在右侧，不紧跟任务内容
- 工作台勾选完成 = 写回笔记中该任务（`- [ ]` → `- [x]`），并同步刷新日历
- 日历任务徽章（蓝点）：**当天有任务记录（含已完成）即保留**，数字=未完成数，全部完成后为 0

### 3.5 生日提醒

- 农历时间只显示**月日**（无年份、无岁数）；头像圆圈内显示**姓氏**
- 30 天内生日显示"还有 N 天"（在公历日期**前**）；公历日期带年份

### 3.6 每日一签

- 非诗句、现代优美语句（每日一签风格，不要"每日一签"四个字角标）
- **分两行展示**：按标点在中点附近断行，两行字数相近
- 按日期哈希确定性生成，每天不同

### 3.7 天气

## 11. 常见问题与解决方案

### 11.1 开发问题

#### Q: 农历库（lunar.js）如何与插件代码共用？

**A:** lunar.js 是 UMD 包，构建时被拼接到 `dist/main.js` 最前面，会把 `module.exports` 设为农历库工厂结果。因此 `main.js` **第一行**必须写 `const lunarLib = module.exports;` 捕获它，文件末尾再 `module.exports = WorkbenchPlugin` 覆盖。

#### Q: 使用生肖 API 报错 `getShengXiao is not a function`？

**A:** lunar-javascript 的实际 API 是小写 `getShengxiao()`（属相）与 `getYearShengXiao()`（生肖），不要写成 `getShengXiao()`。

#### Q: manifest.json JSON.parse 报 Unexpected token ？

**A:** 文件带 BOM（`﻿`）。读取时先剥离 BOM，写入时用 `fs.writeFileSync(path, content, "utf8")`（无 BOM）。不要用 PowerShell `Set-Content` 处理。

#### Q: PowerShell 改完源码后中文变乱码？

**A:** `Get-Content`/`Set-Content` 文本替换会破坏 UTF-8 中文。一律用编辑器 / Write 工具改文件；PowerShell 里 `curl` 也要写成 `curl.exe`（否则是 WebRequest 别名）。

#### Q: 热力图列数/点数如何计算？

**A:** 挂载后测量中栏容器宽度 `w`，`列数 = max(6, floor((w + 4) / 16))`（12px 格 + 4px 间距）；点数 = 列数 × 3（恒 3 行排满）。CSS 用 `repeat(var(--heat-cols), 12px)`，窗口缩放经 ResizeObserver 重绘。无测量宽度时默认 24 列（72 格）。

### 11.2 统计与数据问题

#### Q: 为什么热力图/活跃统计很多天是空白？

**A:** 先看数据本身：热力图统计的是"每天编辑的笔记篇数"，来源是有效最后编辑时间基线（frontmatter `modified` 优先，回退 updated/mtime）+ 编辑日志覆盖。若库是最近新建/迁移的（如 9/3 批量导入），文件系统时间就只有那几天，早于导入日期的历史在磁盘上不存在，无法恢复（除非有 git / Obsidian Sync / 快照）。插件从启用起会用编辑日志精确记录每一次编辑，越用越准。

#### Q: 编辑日志会同步到其他电脑吗？计数准吗？

**A:** editLog 存在插件 `data.json`，随 vault 同步（Obsidian Sync / 网盘）。历史日期同步后准确；唯一偏差场景是两台电脑**同一天**都编辑——data.json 整体覆盖，当天计数只反映最后同步的一台。

#### Q: 本周/本月/本季/本年/近N天为什么都是去重的？

**A:** 用户要求"这个周期内编辑的笔记只会计算一次"。实现：mtime 最后编辑（每篇一次）+ 编辑日志文件列表（本月内存数组）取并集，同篇跨天只算 1。热力图格子本身是"天"维度，显示当天篇数，不去重跨天——两者口径不同但各自正确。

#### Q: 天气不显示 / 换 Key 后仍失败？

**A:** 天气来自和风天气（`qweatherKey` + `qweatherHost`）。检查：1) 设置里 Key 是否正确填入且 `data.json` 已保存；2) Host 默认 `api.qweather.com`，如用代理需填完整 Host；3) 失败时插件降级显示占位，不崩溃。请求频率由 `refreshMinutes` 控制（默认 30 分钟，可调高到每天约 500 次量级以内）。

### 11.3 运行问题

#### Q: 重启 Obsidian 后工作台没自动打开？

**A:** 检查设置里"启动时自动打开工作台"开关（默认开）；`openOnStartup` 依赖 `workspace.onLayoutReady`，若 Obsidian 恢复上次会话可能会被覆盖，手动点 ribbon 图标即可。

#### Q: 任务没显示 / 日历上无徽标？

**A:** 任务只统计 `⏳ scheduled` 日期的（无则回退 `📅 due`）；确认任务在非排除文件夹（`excludeFolders`）内，且用 Obsidian Tasks 标准语法。

#### Q: 任务日期前图案与 Tasks 插件不一致？

**A:** 图标规则：`📅` = scheduled（计划开始）、`⏳` = due（截止），与 Tasks 插件一致；due 日期文字红色显示。

### v1.5.0 补充修复（2026-09-09 同日）——BOM 事故 + 目录创建

**事故**：部署 v1.5.0 后 Obsidian 重启找不到任何社区插件（community-plugins.json 被 Obsidian 写回 `[]`，进入安全模式）。
**根因**（经 Obsidian `electron_debug.log` 控制台确认）：
1. 用 PowerShell 5.1 `Set-Content -Encoding UTF8` 写 `community-plugins.json` 与 manifest.json 会**自动加 UTF-8 BOM（EF BB BF）**；Obsidian 用 `JSON.parse` 读取，**不识别 BOM** → 报 `Unexpected token '﻿'` → community-plugins.json 整体解析失败 → Obsidian 判定配置损坏 → **禁用全部社区插件并写回 `[]`**
2. 4 处 manifest.json（根/src/dist/安装目录）同样带 BOM → 即使启用列表正常，personal-workbench 也无法加载
- 验证方法：启动 Obsidian 时加 `--enable-logging=file` 参数，读 `C:\Users\admin\AppData\Roaming\obsidian\electron_debug.log` 的 `CONSOLE` 行
- **修复**：所有 JSON/配置文件一律用**无 BOM UTF-8** 写入（`[System.Text.UTF8Encoding]::new($false)` 或 Write 工具；**禁用 PS 5.1 的 Set-Content -Encoding UTF8**）；写入后校验前 3 字节非 `EF BB BF`
- **代码修复**（同日发现）：`updateHeatmapLog` 用 `vault.create()` 写 `统计/热力图编辑记录.md`，但 **vault.create 不会自动建目录**——库中无「统计」目录时抛错被吞、文件不生成。已加建目录逻辑（`getAbstractFileByPath` 判断 + `vault.createFolder`），在 Win10-LB（无统计目录）实机验证生成成功
- **经验固化**：Obsidian 插件相关 JSON（community-plugins.json、manifest.json、data.json）**必须无 BOM**；build.js 从 src 复制（无 BOM）不受影响

### v1.5.1 修复（2026-09-09）——任务/生日缓存空数组永久缺失

**现象**（DELL-7480 使用机）：当天任务、今日任务缺失（显示空），热力图正常。
**排查**：直读真实库诊断脚本可扫到 99 条任务、今天（09-09）1 条任务；render-test 真实库渲染今日任务/逾期/后续全部正常 → 数据层与渲染逻辑均无问题，问题在 Obsidian 真实启动时序。
**根因**：getTasks() / getBirthdays() 缓存判断 if (c.data && !c.stale && !force) return c.data;——**JS 中空数组 [] 为 truthy**。Obsidian 启动早期（vault 未加载完）openOnStartup 自动打开工作台 → 首次 scanTasks 扫到 0 个文件 → c.data=[] 被缓存且 stale=false；之后 60s 定时器重渲染命中空缓存直接返回 []，而 metadataCache changed 只在笔记被修改时触发（启动后无修改则不触发）→ **任务/生日永久为空**。诊断脚本与 render-test 均为"库就绪后调用"，故无法复现。
**修复**：两处缓存判断改为 if (c.data && c.data.length && !c.stale && !force) return c.data;——空数组不缓存，每次渲染重新扫描（启动早期扫空后，60s 定时器/下一次渲染即恢复）。天气/扩展缓存因失败时置 stale=true 且带 maxAge，无此问题，未改动。nodeode --check 通过；render-test 107/108（唯一失败为既有 69/69.0 尾数断言，与本修复无关）；DELL 安装目录 main.js 已改并备份 main.js.bak-20260909，共享 Y:\99临时文件\wb-plugin\dist\main.js 已同步（533981B）；源码包 src/main.js 已同步。
**注意**：DELL 是使用机，此修复属紧急热修（直接改安装目录 main.js）；开发机 Win10-LB 从共享拉取源码包后需在开发目录同步此 2 处修改并构建发布（build-push 流程）。

- 根因：computeStats 的**周/月/季/年编辑数、热力图 dayHist、活跃天数、noteList** 均含"mtime 基线"兜底——一篇笔记若只改元属性（如 updated 自动更新），文件 mtime 会变化并被按"最后编辑时间"计入期间 → 误计
